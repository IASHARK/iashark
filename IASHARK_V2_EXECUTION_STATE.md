## i18n (§19) — architecture et état détaillé

**Décision structurelle (demandée explicitement par l'utilisateur, 2026-08-29)** : sous-répertoires `/fr/`, `/en/`, `/es/`, `/de/`, `/it/`, `/pt/` (jamais de sous-domaine ni de query param). FR = langue par défaut (`i18n/locales.json`, champ `default`).

**Architecture technique** (site statique sans bundler, 0 dépendance npm — voir `MODEL_ARCHITECTURE.md` — donc génération par substitution de chaînes pure, pas de parseur HTML externe) :
- `i18n/locales.json` : registre des 6 locales (hreflang, devise, format de date).
- `i18n/dict/{fr,en,es,de,it,pt}.json` : dictionnaires UI partagés (nav, footer, auth, compte, calculateurs, pages) — **119 clés, parité stricte vérifiée par test** (`tests/i18n-build.test.js`), aucune valeur vide.
- `i18n/country-availability.json` : couche future pour restreindre fonctionnalités/commercialisation par pays — structure préparée, **non appliquée** (aucune page ne la lit).
- `i18n/i18n.js` : runtime client partagé — sélecteur de langue, `Intl.DateTimeFormat`/`NumberFormat`/`.currency` pour le formatage runtime (dates/nombres/devise localisés dynamiquement). Ne traduit PAS le contenu statique (voir plus bas pourquoi).
- `scripts/i18n-manifest.js` : manifeste page par page — pour chaque page, les métas (title/description) par locale + une liste de règles `{find, build}` où `find` est un extrait EXACT du fichier source FR et `build(dict, locale, esc)` produit la version traduite. Le build échoue si `find` n'apparaît pas exactement le nombre de fois attendu dans la source (empêche une traduction partielle silencieuse).
- `scripts/build-locales.js` : génère les 6 fichiers réels par page listée dans le manifeste — substitution du texte statique (traduit directement dans le HTML, jamais un swap JS post-chargement, pour un SEO/partage social correct dès le premier octet servi), remplacement title/meta/OG, injection hreflang complet (6 langues + x-default) + canonical, réécriture des liens internes vers les pages localisables (`href="/xxx.html"` → `href="/{locale}/xxx.html"`), `<html lang>`. Commande : `npm run build:i18n`.
- **Pourquoi substitution au build plutôt que dictionnaire chargé au runtime pour le contenu de page** : le MASTER exige "titles/metas traduits ; OpenGraph traduit" — ces balises doivent être correctes dans le HTML brut servi (les scrapers de réseaux sociaux et beaucoup de crawlers ne exécutent pas JS pour ces balises). Le runtime `i18n.js` reste utile pour le sélecteur de langue et le formatage Intl de données dynamiques (dates/nombres issus de data.json), mais pas pour le texte d'interface qui est déjà traduit statiquement dans chaque fichier généré.
- **Bug réel trouvé et corrigé pendant la construction** : une apostrophe non échappée dans une traduction (`AUJOURD'HUI`, FR) injectée dans une chaîne JS entre guillemets simples cassait le script généré (`Uncaught SyntaxError: Unexpected identifier 'HUI'`) — silencieux à la simple lecture du code, détecté uniquement en testant réellement dans le navigateur. Corrigé par une fonction `jsStr()`/`esc()` d'échappement systématique appliquée à toute valeur de dictionnaire injectée dans un littéral JS (jamais dans du texte HTML brut, qui n'en a pas besoin). **Garde-fou permanent ajouté** : `tests/i18n-build.test.js` fait tourner `new Function(code)` sur le JS de chaque page générée × chaque locale — ce test aurait attrapé ce bug automatiquement ; il tourne maintenant à chaque `npm test`.
- `_redirects` : règles i18n ajoutées **après** la ligne `/* /maintenance.html 200!` héritée de `main` — restent totalement inertes tant que la pause du site n'est pas levée (décision de l'utilisateur, jamais automatique). **Règle de sécurité explicite dans le fichier** : n'ajouter une redirection vers `/xx/<page>` que si cette page a réellement été générée pour les 6 locales, sous peine de 404 en cascade dès que la pause serait levée. État actuel : seule la redirection `marches.html → /fr/marches.html` existe (seule page générée à ce jour). Pas de redirection de suggestion de langue sur `/` tant que les 6 pages d'accueil localisées n'existent pas.
- Sitemap international : `sitemap-fr.xml`/`sitemap.xml` sont **régénérés à chaque run du pipeline réel** (pas des fichiers statiques éditables à la main — piège identifié et évité). `generateSitemaps()` dans `update-data.yml` étendue avec `generateLocalizedSitemaps()`, qui `require()` directement `i18n/locales.json` et `scripts/i18n-manifest.js` (même source de vérité que le build lui-même, aucune duplication) pour générer un `sitemap-{locale}-i18n.xml` par langue avec `<xhtml:link rel="alternate">` complet (6 langues + x-default) sur chaque URL, et référence les 6 nouveaux sitemaps dans l'index `sitemap.xml`. Logique testée en isolation (XML bien formé vérifié via `xml.etree.ElementTree`) ; les fichiers réels seront écrits au prochain run réel du pipeline (comme `data.json`, jamais halluciné/écrit à la main ici).
- **Langue ≠ juridiction (respecté explicitement)** : l'avertissement jeu responsable est traduit (le message d'alerte lui-même), mais le numéro d'aide (`joueurs-info-service.fr`, 09 74 75 13 13) reste **volontairement identique et non traduit** dans toutes les langues, avec un label explicite "Help (France):"/"Ayuda (Francia):" etc. — aucune ligne d'aide locale fictive n'est inventée pour l'Espagne/Allemagne/Italie/Portugal/UK. Les pages légales (`cgv.html`, `mentions-legales.html`, `confidentialite.html`) ne sont PAS encore traduites (à faire avec la même prudence : traduction pour compréhension uniquement, jamais réécrites comme des CGV locales d'un autre pays).

**Page pilote (preuve complète, vérifiée en direct)** : `marches.html` — 6 fichiers générés (`/fr/`, `/en/`, `/es/`, `/de/`, `/it/`, `/pt/marches.html`), title/meta/OG/hreflang/canonical corrects par locale, contenu HTML statique traduit (nav, footer, disclaimer, catalogue de marchés, table des marchés du jour), contenu JS-généré traduit aussi (STATUS_LABEL, CATEGORY_LABEL — bug d'origine trouvé et corrigé au passage, `CATEGORY_LABEL` existait mais n'était jamais utilisé dans le rendu —, DATA_QUALITY_LABELS — même bug —, MARKET_KEY_LABELS, messages d'état vide, en-têtes de tableau). Les prédicats de correspondance JS qui matchent le contenu brut non localisé de `data.json` (`getMarketKey()`) sont volontairement **non traduits** — `data.json` reste une ressource globale partagée entre toutes les langues. Vérifié en direct dans le navigateur pour FR (régression zéro vs l'original), EN, ES, IT (cas apostrophe) : rendu correct, zéro erreur console, `document.title` correct par locale.

**Reste à faire pour l'i18n** (pages prioritaires du MASTER, par ordre) : Accueil (`index.html`), page Match (`match.html`), Outils (`pro.html`), Archives (`historique.html`), Compte/connexion (`compte.html`), Tarifs/PRO (`landing.html`), puis navigation/footer partagés déjà couverts par le dictionnaire commun.
